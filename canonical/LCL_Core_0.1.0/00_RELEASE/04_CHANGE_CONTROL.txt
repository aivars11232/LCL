LCL CORE 0.1.0 RELEASE CANDIDATE
CHANGE CONTROL
NORMATIVE

Published release bytes are immutable and may never retain the same checksum
after an edit. This repair tree is a blocked candidate, not an established
release; it retains the historical candidate version only while it remains
unpublished. Before any release, the owner must adjudicate whether accepted
repairs change language meaning and select the corresponding semantic version.
Corrections that change no meaning require a patch release. Added
backward-compatible features require a minor release. Breaking lexical, grammar,
type, or semantic changes require a major release. Every packaged candidate or
release receives freshly generated integrity metadata.

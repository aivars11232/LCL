2. LANGUAGE BOUNDARY

The language consists of source notation, vocabulary, lexical rules, types and
values, grammar, expressions, declarations, control flow, diagnostics, semantics,
standard-library contracts, versioning and conformance requirements in this
package. Every normative artifact needed to read the language is included.

WORKSPACE is a language declaration of an explicit path base and access bounds;
it is not a workspace-management application. Filesystem, process and network
operations have abstract target, parameter, dependency, effect, result and error
contracts. Those contracts define observable language behavior without requiring
this package to contain a host, product, provider or executable implementation.

A UI, IDE, workspace/project manager, portal, desktop controller, provider
connector, database implementation, agent framework, compiler, interpreter,
parser, runtime or executable conformance engine is outside this completion.
Their absence does not make the bare-language specification incomplete.

3. INTERPRETATION INPUT

A conforming LC may use only the LCL source and sources explicitly referenced by
that source as normative task input. Unreferenced chat history, hidden memory,
provider defaults and historical task packages cannot alter LCL meaning.

4. UNKNOWN FEATURES

Syntax, keywords, symbols, identifiers, fields, operations or types absent from
this version's closed registries are rejected. They are not guessed.

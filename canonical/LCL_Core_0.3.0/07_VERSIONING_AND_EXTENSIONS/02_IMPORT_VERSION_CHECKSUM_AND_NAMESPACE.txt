LEARNED COMPUTING LANGUAGE (LCL)
TITLE: Import Version, Checksum, and Namespace
LANGUAGE VERSION: 0.3.0
STATUS: NORMATIVE
DATE: 2026-09-05


IMPORT VERSION must equal imported SPECIFICATION.VERSION. LCL version must be
supported independently. SOURCE PATH resolves relative only to importing file or
explicit WORKSPACE. URI requires CHECKSUM. Checksum form is
algorithm:lowercase_hex; Core 0.3.0 recognizes only sha256. Namespace is
mandatory, unique, lowercase, and not reserved.
Import cycles fail. Imported IDs are referenced namespace.id.

An IMPORT or EXTENSION namespace owns its complete first identifier segment in
the importing document. No local declaration ID or second imported namespace
may occupy that segment; for example, namespace library and a local ID
library.value collide and use error.id.duplicate. Duplicate namespace ownership
also uses error.id.duplicate. A missing, malformed, or reserved namespace uses
error.namespace.invalid, except that omission of the required NAMESPACE field
is the more specific schema diagnostic error.field.required. User declaration
IDs whose first segment is reserved use error.namespace.invalid.

Resolve an imported declaration's unqualified document-local identifiers in
the original source document, including that document's own imports. Qualifying
the declaration as namespace.id exposes that same declaration and does not
rebind its internal references to names in the importing document. Qualified
access never strips or guesses namespace segments, and no imported declaration
is silently merged into the local namespace. Distinct acyclic import paths do
not override one another or weaken exact version/checksum validation.

In a project, IMPORT and EXTENSION are declared only by the kind.project entry,
and their namespaces are owned in the whole project namespace. A PART is not
an import: it declares no namespace and no VERSION, and its declarations join
the project namespace under 05_SEMANTICS/13_PROJECTS_PARTS_AND_PROJECT_ADMISSION.txt.

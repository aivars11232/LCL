LEARNED COMPUTING LANGUAGE (LCL)
TITLE: Custom Types, Schemas, and Definitions
LANGUAGE VERSION: 0.1.0
STATUS: NORMATIVE
DATE: 2026-08-31


DEFINE KIND rules:

kind.term
    MEANING required.
kind.constant
    TYPE and VALUE required.
kind.type
    BASE required and is one TYPE_EXPRESSION, including REF(identifier)
    resolving to kind.type. A direct BASE OBJECT requires one or more FIELD
    and defines their exact object schema. A direct BASE ENUM requires one or
    more distinct ITEM simple identifiers and defines a concrete enum domain.
    Every other BASE is a transparent alias of its resolved type, including
    the same enum domain or object schema when aliasing a defined type. FIELD
    is legal only with direct BASE OBJECT; ITEM only with direct BASE ENUM.
    An alias cannot add fields, members, refinements, or conversion rules.
    REF(type.id) selects that type wherever a source type is required;
    OBJECT[REF(type.id)] additionally requires an object schema.
    Enum ITEM values resolve against the one concrete enum type required by
    the containing typed value or operator operand. The same ITEM spelling in
    different enum domains denotes different typed values. Without one
    expected enum domain, an unqualified enum ITEM is not resolved by guessing.
    A nonmember or ambiguous enum value uses error.type.mismatch. Bare ENUM
    is legal as this definition base or when an operation contract supplies
    one exact enum domain; it cannot declare an unconstrained material value.
kind.operation
    MEANING, SIDE_EFFECT, DETERMINISTIC required; optional DEPENDENCY; zero or
    more PARAMETER and at most one RESULT. SIDE_EFFECT, DEPENDENCY, and
    DETERMINISTIC are separate contract axes. A custom operation declares its
    complete axis contract in its own definition and selects no implementation
    profile, so every property the language requires of it is expressible in
    LCL. SIDE_EFFECT FALSE declares possible effects exactly {none}. SIDE_EFFECT
    otherwise takes one LIST of one or more distinct concrete effect classes
    from the closed effect vocabulary and forbids none; that list is the
    operation's possible-effect maximum. DEPENDENCY takes one LIST of one or
    more distinct classes from the closed dependency vocabulary; an omitted
    DEPENDENCY declares exactly {declared_state_only}.
    declared_state_only denotes no external dependency class and none denotes
    no concrete effect class when declared bounds are checked. An invocation
    resolves its effect set from the address classes of its resolved TARGET and
    declared destination arguments, bounded by the declared maximum. An
    invocation that would resolve an effect class outside that maximum, and a
    declared effect-class maximum whose invocation resolves no concrete effect
    class, each emits error.operation.precondition and cannot begin effects.
    DETERMINISTIC TRUE is a verified assertion over the fully resolved built-in
    operation or the declared custom-operation contract, using identical
    declared inputs, dependency snapshots, and the declared dependency and
    effect axes.
    It is not an override. It is valid only when the resolved contract is
    deterministic; otherwise validation emits error.determinism.mismatch with
    terminal status.invalid. A custom operation may assert TRUE only when its
    declared axes and parameters admit no permitted variation. DETERMINISTIC
    FALSE conservatively permits either deterministic behavior or only the
    bounded variation admitted by the resolved operation contract; it never
    relaxes another rule.
kind.format
    MEANING required; optional BASE/ENCODING. BASE is a core format identifier
    or the ID of a kind.format definition. ENCODING is one core registered
    encoding.
kind.event, kind.status, kind.error
    MEANING and BASE required. BASE names one core identifier of the same
    domain or one acyclic same-kind alias. These definitions are aliases,
    not additional core events, statuses, or errors. Resolve BASE transitively
    to its canonical core identity before event matching, diagnostic metadata
    and ranking, status transitions, or equality. Every core metadata and
    lifecycle property is inherited without modification. An unresolved BASE
    uses error.reference.unresolved, a wrong-domain BASE error.reference.kind,
    and an alias cycle error.reference.cycle.

Definitions are immutable and may reference earlier or later definitions so long
as resolution is acyclic. Anonymous SCHEMA is local to its containing value.

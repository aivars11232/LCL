LEARNED COMPUTING LANGUAGE (LCL)
TITLE: Core Block Schemas B
LANGUAGE VERSION: 0.1.0
STATUS: NORMATIVE
DATE: 2026-08-30


REQUIRE
    Contexts: top_level
    Occurrence: zero_or_more
    Required: ID
    Optional: ASSERT, ACTION, WHEN, SCOPE, AUTHORITY, PRIORITY, EVIDENCE, DESCRIPTION
    Repeatable: none
    Rule: Exactly one ASSERT or ACTION.
    Rule: Hard rule.
    Rule: ACTION is reference/list-only; an inline ACTION block is forbidden.
    Rule: Optional PRIORITY defaults to 0, never inherits, and an explicit declaration overrides the default.

PREFER
    Contexts: top_level
    Occurrence: zero_or_more
    Required: ID
    Optional: ASSERT, ACTION, WHEN, SCOPE, AUTHORITY, PRIORITY, DESCRIPTION
    Repeatable: none
    Rule: Exactly one ASSERT or ACTION.
    Rule: Soft and does not authorize action.
    Rule: ACTION is reference/list-only; an inline ACTION block is forbidden.
    Rule: Optional PRIORITY defaults to 0, never inherits, and an explicit declaration overrides the default.

PRESERVE
    Contexts: top_level
    Occurrence: zero_or_more
    Required: ID, TARGET
    Optional: PROPERTY, WHEN, SCOPE, AUTHORITY, PRIORITY, EVIDENCE, DESCRIPTION
    Repeatable: PROPERTY
    Rule: No PROPERTY means complete target.
    Rule: Hard pre-state equals post-state rule.
    Rule: Optional PRIORITY defaults to 0, never inherits, and an explicit declaration overrides the default.

OVERRIDE
    Contexts: top_level
    Occurrence: zero_or_more
    Required: ID, WINNER, LOSER
    Optional: WHEN, DESCRIPTION
    Repeatable: none
    Rule: Exact conflicting clauses only.
    Rule: Lower authority cannot win.

PHASE
    Contexts: top_level
    Occurrence: zero_or_more
    Required: ID
    Optional: MODE, STEP, SEQUENCE, BEFORE, AFTER, WHEN, REQUIRED, DESCRIPTION
    Repeatable: STEP
    Rule: At least STEP, SEQUENCE, IF, or FOR EACH.
    Rule: MODE defaults mode.sequential.

SEQUENCE
    Contexts: top_level, PHASE
    Occurrence: zero_or_more
    Required: ID
    Optional: MODE, STEP, WHEN, REQUIRED, DESCRIPTION
    Repeatable: STEP
    Rule: At least STEP, IF, or FOR EACH.
    Rule: Lexical order is normative.

STEP
    Contexts: SEQUENCE, PHASE, IF, FOR_EACH, ELSE
    Occurrence: one_or_more
    Required: ID
    Optional: ACTION, SEQUENCE, PHASE, TASK, BEFORE, AFTER, WHEN, REQUIRED, HANDLER, DESCRIPTION
    Repeatable: none
    Rule: Exactly one ACTION, SEQUENCE, PHASE, or TASK.
    Rule: SEQUENCE and PHASE fields are reference/list-only; inline SEQUENCE or PHASE blocks are forbidden.

RETRY
    Contexts: ACTION
    Occurrence: zero_or_one
    Required: LIMIT
    Optional: WHEN, DELAY, HANDLER, DESCRIPTION
    Repeatable: none
    Rule: LIMIT counts additional attempts and is 0 through 100.
    Rule: This inline ACTION block is the only source of attempt bounds; total attempts are at most 1 + LIMIT and the first successful attempt ends retrying.
    Rule: A handler using core.retry authorizes this declared RETRY and its resolved limit must equal this LIMIT.
    Rule: RETRY.WHEN defaults to TRUE and RETRY.DELAY defaults to DURATION(0, unit.second). A false condition or a refused safety check prevents another attempt without manufacturing count exhaustion or success.
    Rule: Count exhaustion occurs only after 1 + LIMIT actual unsuccessful attempts.
    Rule: RETRY.HANDLER is in scope only for diagnostics raised by an attempt of the ACTION declaring this RETRY, including the first attempt.

HANDLER
    Contexts: top_level
    Occurrence: zero_or_more
    Required: ID, EVENT, OPERATION
    Optional: TARGET, PARAMETER, WHEN, FALLBACK, LIMIT, DESCRIPTION
    Repeatable: PARAMETER
    Rule: HANDLER is an invocation site; OPERATION selects and invokes one operation under the ACTION contract.
    Rule: EVENT names the event this handler activates on; the closed event model in statuses_and_errors_v0.1.0.json#/event_model raises events only from emitted diagnostics and selects at most one handler per raised diagnostic.
    Rule: A required TARGET may be omitted only under the handler-context binding for REFERENCE[ACTION] or REFERENCE[meta.execution_unit] targets.
    Rule: LIMIT is exactly the limit named parameter of the selected operation and is legal only when that operation registers it.
    Rule: FALLBACK admits one REF to a HANDLER, or one operation identifier that requires no named parameter and whose required TARGET the handler-context binding supplies.
    Rule: An injected handler-context target identifies the active owning invocation aggregate; the failed child attempt remains immutable evidence. Explicit targets follow the selected operation contract.
    Rule: At most one handler is selected through event attachments; direct acyclic FALLBACK calls may invoke another HANDLER without a second event selection.

OUTPUT
    Contexts: top_level
    Occurrence: zero_or_more
    Required: ID, TYPE, FORMAT
    Optional: TARGET, SCHEMA, ENCODING, REQUIRED, DEFAULT, PROPERTY, DESCRIPTION
    Repeatable: PROPERTY
    Rule: TARGET is destination, not produced VALUE.
    Rule: Zero PROPERTY occurrences select the applicable default result; one selects a scalar field; two or more select a closed OBJECT in declaration order.
    Rule: Every PROPERTY is unique and must name an available projectable result field.

VALIDATE
    Contexts: top_level
    Occurrence: zero_or_more
    Required: ID, ASSERT
    Optional: TARGET, ERROR, WHEN, REQUIRED, EVIDENCE, DESCRIPTION
    Repeatable: none
    Rule: Runs before first side effect.

VERIFY
    Contexts: top_level
    Occurrence: zero_or_more
    Required: ID, ASSERT
    Optional: TARGET, ERROR, WHEN, REQUIRED, EVIDENCE, DESCRIPTION
    Repeatable: none
    Rule: Runs after observed target exists.
    Rule: Required failure prevents success.

TEST
    Contexts: top_level
    Occurrence: zero_or_more
    Required: ID
    Optional: TASK, ACTION, INPUT, EXPECTED, ACTUAL, ASSERT, EVIDENCE, REQUIRED, DESCRIPTION
    Repeatable: none
    Rule: At least ASSERT or EXPECTED+ACTUAL.
    Rule: At most one TASK/ACTION.

EVIDENCE
    Contexts: top_level
    Occurrence: zero_or_more
    Required: ID, TYPE
    Optional: SOURCE, VALUE, FORMAT, ENCODING, CHECKSUM, PROVENANCE, REQUIRED, DESCRIPTION
    Repeatable: none
    Rule: Exactly one SOURCE or VALUE when evaluated.

SUCCESS
    Contexts: top_level
    Occurrence: zero_or_more
    Required: ID
    Optional: ALL, ANY, NONE, DESCRIPTION
    Repeatable: none
    Rule: Exactly one ALL, ANY, or NONE.

FAILURE
    Contexts: top_level
    Occurrence: zero_or_more
    Required: ID, WHEN, STATUS
    Optional: ERROR, HANDLER, EVIDENCE, DESCRIPTION
    Repeatable: none
    Rule: STATUS is terminal non-success.
    Rule: Resolve status aliases first. A selected STATUS must be legal in the active producer current allowed_next set and scope; an illegal transition produces error.execution.order, and an execution root cannot select status.skipped.
    Rule: The first TRUE FAILURE in source order maps status only when no primary unhandled diagnostic fixes it; ERROR is classification metadata and does not emit an arbitrary new diagnostic.

ASSUME
    Contexts: top_level
    Occurrence: zero_or_more
    Required: ID, TARGET, VALUE, WHEN
    Optional: SCOPE, EVIDENCE, DESCRIPTION
    Repeatable: none
    Rule: Never overrides explicit data.
    Rule: Applied assumption appears in evidence.

EXECUTE
    Contexts: top_level
    Occurrence: zero_or_one
    Required: REFERENCE
    Optional: MODE, OUTPUT, DESCRIPTION
    Repeatable: none
    Rule: Reference is TASK, PHASE, SEQUENCE, ACTION, or TEST.
    Rule: task/test documents require exactly one.

COMMENT
    Contexts: top_level, IF, FOR_EACH, ELSE
    Occurrence: zero_or_more
    Required: CONTENT
    Optional: none
    Repeatable: none

EXAMPLE
    Contexts: top_level, DEFINE
    Occurrence: zero_or_more
    Required: ID, CONTENT
    Optional: EXPECTED, REQUIRED, DESCRIPTION
    Repeatable: none
    Rule: REQUIRED defaults FALSE.

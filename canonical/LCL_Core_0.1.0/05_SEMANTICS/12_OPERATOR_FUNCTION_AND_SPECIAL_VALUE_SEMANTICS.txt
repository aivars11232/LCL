LCL CORE 0.1.0 RELEASE CANDIDATE
OPERATOR, FUNCTION, AND SPECIAL-VALUE SEMANTICS
NORMATIVE

Operator arity, operand-family, result-family, precedence,
associativity, numeric-promotion, ordered-type, string-ordering, and UNKNOWN
truth-table records are stored in:

    10_REGISTRIES/operators_and_functions_v0.1.0.json

That registry also closes the typed-constructor names, overloads, results,
constraints, and diagnostics. A constructor call is pure. An unregistered name,
arity, or operand family is invalid; implementations do not infer extra overloads.
Its signature_notation defines every local signature designator, including
numeric, ordered, same_unit_MEASURE_collection, and every dependent result family.
Those are specification terms, not source types or an extension of the separate
operation/result contract-type notation. All pure-function and constructor
arguments are positional; no function in this release declares named arguments.

Every expression is statically checked, including names and operand families in
a branch that will not be evaluated. Evaluation proceeds left to right through
operands, arguments, collection members, and postfix bases/indices, stopping at
the first diagnostic. AND skips its right operand only when the left result is
FALSE. OR skips its right operand only when the left result is TRUE. UNKNOWN on
the left requires the right result. All other pure functions and operators are
eager; immediate quantifier sequences evaluate every member before reduction.

Consuming MISSING produces error.required.missing except for ==, !=, and EXISTS.
An absent valid property or index selection may itself yield MISSING. UNKNOWN
propagates through arithmetic, constructors, ordered comparisons, membership,
containment, matching, ordinary pure functions, and postfix access after required
operands have been evaluated and MISSING checked. A concrete subexpression
diagnostic is never suppressed by UNKNOWN elsewhere. Static material result
families are lifted to these non-material outcomes; this creates no storable
UNKNOWN type. A required material destination rejects UNKNOWN with
error.value.unknown. Equality, EXISTS, Boolean operators, and quantifiers have
their explicit special rules. All row-local errors are additional to these common
evaluation errors and the errors of evaluated subexpressions.

== always returns BOOLEAN; != is its negation. Each singleton sentinel equals
itself and differs from the other sentinel and every material value. Different
material static types are unequal except for exact INTEGER/DECIMAL comparison.
MEASURE equality compares both exact unit identifier and numeric magnitude;
different units produce FALSE. This does not relax ordered comparison or any
same-unit arithmetic overload.
REF uses types_v0.1.0.json#/reference_context_contract: ordinary value operands
read a value-bearing declaration once, and a resulting stored REFERENCE retains
its identity without another dereference. Two resulting REFERENCE values compare
resolved declaration or loop-instance identity. No coercion makes references,
strings, booleans, or quantities equal to numbers.

IN tests strict-equality membership. Collection CONTAINS reverses IN; OBJECT
CONTAINS tests exact STRING key presence. STRING CONTAINS tests a contiguous exact
Unicode-scalar substring, and the empty substring is present in every STRING.
Membership in an empty collection is FALSE once both operands are material.

LIST indexing is zero-based. Every INTEGER below zero or at least the member
count yields MISSING; negative indices never wrap. OBJECT STRING indexing selects
an exact, statically known property so its result has one exact field type;
a runtime-varying key uses error.operator.operand. An absent optional schema
field or absent schema-free OBJECT
field yields MISSING; a field not admitted by a closed schema uses
error.operator.operand. Lowercase property access selects an evaluated OBJECT
field under the same presence rules. A reserved uppercase property directly after
REF, with optional parentheses around that REF, selects registered declaration
metadata before a bound-value read. SET and STRING indexing are not admitted.

Bracket expressions default to LIST. One exact immediate expected SET[T] type
selects SET instead. A known expected member type applies to each member and to
nested empty literals; otherwise all members must have the same static type,
without collection-construction numeric promotion. An empty literal without one
unique contextual member type produces error.type.mismatch. Accordingly an
unconstrained COUNT([]) is invalid, while COUNT of an already typed empty
collection is zero. Source order evaluates every SET source member before
strict-equal duplicates collapse.

ALL, ANY, and NONE supply BOOLEAN context to an immediate bracket argument.
They also accept a material LIST[BOOLEAN]. An immediate sequence may contain
UNKNOWN observations, but such a sequence is non-material and exists only while
that call reduces it; it cannot be stored, nested as data, indexed, returned, or
passed through another function. Parentheses around the immediate sequence do
not change that rule. This immediate quantifier argument explicitly permits
UNKNOWN literals even outside another condition. A MISSING member emits
error.required.missing, and a
member of another material family emits error.operator.operand.

ALL returns FALSE if any member is FALSE, else UNKNOWN if any member is UNKNOWN,
else TRUE. ANY returns TRUE if any member is TRUE, else UNKNOWN if any member is
UNKNOWN, else FALSE. NONE is NOT of ANY. Thus ALL([]) and NONE([]) are TRUE and
ANY([]) is FALSE. The complete three-valued Boolean tables are registered; neither
UNKNOWN nor MISSING is silently converted to FALSE.

COUNT counts Unicode scalars in STRING, occurrences in LIST, unique SET members,
and present OBJECT properties. COUNT(BYTES(n)) returns INTEGER n. EMPTY is TRUE
exactly when COUNT is zero; NULL is not an accepted family. SUM, MIN, and MAX
require nonempty collections and reject a typed empty collection with
error.operator.operand. SUM returns the exact mathematical sum in the registered
member family, with one exact unit for MEASURE; it never invents an empty-sum unit.
MIN/MAX use the registered total order. SET source order never changes a reduction.

The registered total-order profile is also the sole natural-order source for SET
iteration and core.sort. INTEGER and DECIMAL use exact mathematical value; STRING
uses Unicode-scalar lexicographic order; and DATE uses chronological Gregorian
full-date order. TIME subtracts its declared offset, or +00:00 when omitted, on a
common nominal local date and retains signed previous-day or next-day displacement
without modulo-24-hour wrapping. DATETIME uses its exact offset-normalized UTC
instant. DURATION uses the normalized exact magnitude and nanosecond factors in
formats_encodings_units_v0.1.0.json#/duration_normalization. PERCENTAGE and BYTES
use exact magnitude, and MEASURE values are order-compatible only with the same
exact UNIT and compare by numeric component. Within one declared ordered type,
equal canonical order keys are strict-equal values and collapse as SET duplicates
before ordering. MISSING and UNKNOWN are not orderable. No locale, insertion
order, host collation, or inferred ENUM order may change these rules.

MATCHES consumes STRING and REGEX, or PATH/STRING and GLOB. It compares the
entire input under the selected closed pattern profile. A non-match returns FALSE.
For REGEX, full-string behavior is a semantic boundary check and is not expressed
by adding start/end anchors, because multiline mode would weaken that substitution.
Pattern compilation or matching that exhausts the declared finite resource limit
produces error.pattern.resource_limit.

No implicit string-to-number, Boolean-to-number, path-to-string, enum-to-string,
or unit conversion exists. INTEGER promotes to DECIMAL only when paired with
DECIMAL outside division; every scalar division overload has static result type
DECIMAL. MEASURE divided by INTEGER or DECIMAL preserves its exact UNIT and has
a DECIMAL numeric component. MEASURE divided by a MEASURE with the same exact
UNIT returns dimensionless DECIMAL; different units produce
error.numeric.unit_mismatch, and numeric divided by MEASURE is not registered.
Ordered MEASURE comparison continues to require the same exact UNIT.

Division computes an exact mathematical quotient. A finite base-10 result is
required unless the quotient is the direct first argument of ROUND, which rounds
once using half-even to a declared non-negative number of fractional digits.
ROUND also accepts MEASURE and preserves its UNIT. TOLERANCE does not establish a
rounding context. Mathematical-zero denominators always produce
error.numeric.division_by_zero. Other non-terminating quotients produce
error.numeric.non_terminating. Host limitations produce error.host.constraint
without changing the required value; no overflow, wrap, saturation, Infinity,
NaN, or underflow-to-zero result exists in LCL.

COMMON UNIT CONSTRAINT

Every arithmetic, ordered-comparison, SUM, MIN, or MAX overload that requires
identical MEASURE units emits error.numeric.unit_mismatch for unequal concrete
unit identifiers. Equality and inequality instead use their explicit different-
unit FALSE/TRUE rules.

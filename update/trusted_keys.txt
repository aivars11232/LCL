# The update signing keys this build of LCL trusts, one per line:
#
#   <key id> <hex of the key's SubjectPublicKeyInfo DER: an ECDSA P-256 public key>
#
# Both the PC updater (lcl-update) and LCL for Android read this file when they
# are built, so one release is judged by one list everywhere. Only public keys
# belong here; the private key lives offline, outside the repository.
#
# A key id is 1 to 64 of a-z, 0-9 and "-". A manifest names the key that signed
# it, and a key that is not listed here is never trusted, whatever a manifest
# says.
#
# One key, kept: Update System V1 has exactly one production update signing
# key and never replaces it. Listing a next key here beside it would not make a
# replacement safe, because LCL checks only the latest stable release: a PC or
# phone that skipped the release that introduced the next key could never
# verify a release signed with it. Replacing the key is a separate feature that
# is not designed yet.
#
